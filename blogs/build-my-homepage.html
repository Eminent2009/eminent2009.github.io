这个主页的第一版只有一张头像和一句签名，剩下的全是空白。后来我想，与其一直放着， 不如把它当作一个练手项目：不引入框架，不配置构建工具， 只用浏览器能直接读懂的三样东西——HTML、CSS、JavaScript，把它从零做出来。 这篇文章记录的就是完整的搭建过程，包括每一步的代码、我踩过的坑，以及最后怎么免费部署上线。

目标不是做出一个“很厉害”的网站，而是完整走通一次：设计 → 编码 → 数据 → 部署。

为什么要自己写主页

现在有很多现成的主页模板，甚至用在线工具几分钟就能生成一个。但自己写仍然有意义， 原因大概有三个：

  • 完全可控：颜色、间距、字号、动效都由自己决定，不用迁就模板的结构。
  • 理解原理：从浏览器如何解析 HTML，到 fetch 如何拿数据、如何渲染，都是真实可见的。
  • 沉淀资产：博客数据、文章页面、部署仓库都是自己的，以后可以慢慢迭代。

另外，个人主页是一个非常好的“试验田”。想试新的 CSS 特性、想练响应式布局， 都可以先在这里动手，坏了也不会影响任何人。

这篇文章假设你会一点点 HTML 和 CSS。如果完全没接触过，建议先花半小时看看标签和选择器的基础，再回来跟着做。

开工前的准备

需要的工具非常少，都是免费的：

  1. 一个编辑器，VS Code 或任意顺手的都可以；
  2. 一个现代浏览器，用来预览和调试；
  3. Git，用来管理版本；
  4. 一个 GitHub 账号，用来托管和部署。

最终的项目结构不复杂，提前规划好目录能省掉很多路径问题。我的结构是这样的：

项目结构 
eminent2009.github.io/
├── index.html          # 首页：头像、博文列表、联系方式
├── javascript.js       # 读取数据、渲染卡片、分页
├── blogs.json          # 博文元数据（标题、封面、链接等）
├── 404.html            # 文章不存在时的兜底页
├── css/
│   └── style.css       # 自定义样式（滚动、动效）
├── data/
│   └── imgs/           # 头像、Logo、封面图
└── blogs/
    └── build-my-homepage.html  # 文章详情页（你正在看的这页）

这里刻意没有 node_modules、没有打包配置。所有文件都可以直接被浏览器打开， 部署时也只是把整个目录推到 GitHub 上。

搭出页面骨架

先写 HTML。骨架阶段不追求好看，重点是结构清晰、语义正确： 用 header 放头像和名字，用 section 放博文列表，用 footer 放联系方式。

index.html 
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>NullShade - 个人主页</title>
  <script src="https://cdn.tailwindcss.com"></script>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
  <header>头像 + 名字</header>
  <section id="blogs">
    <div id="blogs-container"></div>  <!-- 卡片由 JS 生成 -->
    <div id="pagination"></div>
  </section>
  <footer>联系方式</footer>
  <script src="javascript.js"></script>
</body>
</html>

有两个细节值得单独说：

  • lang="zh-CN" 告诉浏览器页面是简体中文，影响断行和部分辅助功能；
  • viewport 这行是移动端适配的前提，没有它手机上会按桌面宽度缩放，字会小到看不清。

骨架阶段可以先不写 CSS，把内容按从上到下的顺序堆出来。结构对了，后面加样式只是“锦上添花”，不会返工。

用 Tailwind 写样式

为了不写一大堆重复的类名，我选择用 Tailwind 的工具类。通过 CDN 引入后， 在 <head> 里扩展主题色，就能全站复用：

index.html · tailwind.config 
tailwind.config = {
  theme: {
    extend: {
      colors: {
        primary: '#4F46E5',   // 主色：靛蓝
        secondary: '#F3F4F6', // 次要色：浅灰
        dark: '#1F2937',      // 正文深灰
      },
    }
  }
}

定好颜色之后，卡片的网格布局只需要一行类名：

index.html · 卡片容器 
<div id="blogs-container"
     class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-8">
</div>

这行类名的意思是：手机上一列，平板两列，桌面三列，间距 2rem。 用传统 CSS 要写好几段媒体查询，这里一个类就表达了完整意图。

封面图区域还用了 aspect-square + object-cover： 无论原图尺寸如何，都裁成正方形，卡片高度才能整齐。卡片悬浮上浮的效果则放在 css/style.css 的 .card-hover 里，用过渡加位移实现。

这是我最开始踩的坑：Tailwind CDN 不会处理外部 CSS 文件里的 @apply。 把 @apply 写进 css/style.css，浏览器会原样忽略，类名等于没写。 解决办法二是把自定义类改成原生 CSS 属性，要么用正式构建流程（CLI / Vite）。我选了前者。

让布局适配手机

响应式的核心就两件事：宽度用相对单位，布局按断点切换。 这个页面主要用了三种手段：

  • 标题字号用 clamp(1.8rem, 4vw, 2.5rem)，随视口平滑变化，不会突然跳变；
  • 卡片网格用 grid-cols-1 md:grid-cols-2 lg:grid-cols-3；
  • 右侧悬浮头像在 md 以下直接隐藏，避免遮挡内容。

正文区域则限制了最大宽度。中文一行太长会很难读，移动端靠内边距控制， 桌面端交给 max-w-6xl mx-auto 居中。

调试时别只看缩放窗口，用浏览器的“设备模拟”功能，切到 iPhone 和 iPad 尺寸各看一遍，重点检查文字换行和图片裁切。

用 JSON 管理文章数据

如果每发一篇文章都要改 HTML，很快就会乱。所以我抽了一个 blogs.json，每篇文章是一个对象，页面只负责读取和渲染：

blogs.json 
[
  {
    "image": "./data/imgs/cover.jpg",   // 封面图地址
    "title": "零基础搭建个人主页：从 0 到 1",
    "description": "一句话简介，卡片上最多显示三行",
    "date": "2025-10-20",
    "url": "./blogs/build-my-homepage.html"
  }
]

JSON 有一个限制：标准 JSON 不支持注释。写了 // 或 /* */， JSON.parse 会直接报错，页面就白屏了。我的做法是加一个下划线开头的 _comment 字段，渲染时用不到，纯粹当备忘录：

blogs.json · 注释写法 
{
  "_comment": "每个对象是一张卡片；date 只是展示文本，不参与排序",
  "title": "..."
}

读取数据用 fetch，并且一定要包一层 try/catch：

javascript.js · loadBlogs 
async function loadBlogs() {
  try {
    const response = await fetch('./blogs.json');
    blogs = await response.json();
    renderBlogs();
    renderPagination();
  } catch (error) {
    console.error('加载博客数据失败:', error);
  }
}

直接双击打开 index.html（file:// 协议）时，浏览器会因为安全策略拒绝 fetch 本地文件，控制台报 CORS 错误，卡片一张都不显示。 解决办法是起一个本地服务器，例如在项目目录执行 python3 -m http.server 8000， 然后访问 http://localhost:8000。

渲染卡片与分页

数据拿到之后，渲染逻辑其实很直接：算出当前页的区间，循环生成 DOM，再塞进容器。

javascript.js · renderBlogs（节选） 
const startIndex = (currentPage - 1) * blogsPerPage;
const currentBlogs = blogs.slice(startIndex, startIndex + blogsPerPage);

currentBlogs.forEach(blog => {
  const card = document.createElement('div');
  card.className = 'bg-white rounded-lg shadow-md overflow-hidden';
  card.innerHTML = `
    <img src="${blog.image}" alt="${blog.title}">
    <h3>${blog.title}</h3>
    <p>${blog.description}</p>
  `;
  blogsContainer.appendChild(card);
});

分页控件根据总页数动态生成：先算 Math.ceil(blogs.length / blogsPerPage)， 再渲染上一页、页码、下一页。只有一页时不显示分页，避免页面上出现无意义的按钮。

部署到 GitHub Pages

页面写完，最后一步是让它真正可以访问。GitHub Pages 对纯静态站点免费， 而且仓库名用 用户名.github.io 时，访问地址就是根路径，最省事。

终端 
# 1. 初始化仓库并提交
git init
git add .
git commit -m "init: 个人主页"
git branch -M main

# 2. 关联远程仓库（换成你自己的地址）
git remote add origin https://github.com/eminent2009/eminent2009.github.io.git
git push -u origin main

推送完成后，在仓库的 Settings → Pages 里确认发布分支是 main、 目录是 / (root)。等一两分钟，访问 https://用户名.github.io 就能看到页面了。

因为站点部署在子路径或根路径下，站内链接一律用相对路径 （./blogs/xxx.html），不要写死 /blogs/xxx.html， 否则换域名或换仓库名时整站链接都会失效。

踩过的坑

把整个过程里最有代表性的几个问题整理成表，遇到类似现象可以先对照排查：

现象 原因 解决方式
卡片完全不显示，控制台无报错 用 file:// 打开，fetch 被拦截 起本地服务器：python3 -m http.server
控制台报 JSON 解析错误 在 JSON 里写了 // 注释或多余的逗号 改用 _comment 字段；提交前校验格式
自定义类完全没生效 CDN 模式不处理外部 CSS 里的 @apply 改写原生 CSS，或改用 Tailwind 构建流程
部署后图片 404 路径大小写不一致，或用了绝对路径 核对文件名，统一使用相对路径
点“阅读更多”跳到 404 url 指向的文章页还没创建 在 blogs/ 下补上对应 HTML，或先隐藏该条数据
手机上字号特别小 缺少 viewport meta 标签 补上 width=device-width, initial-scale=1.0

小结

整个主页没有用到任何框架，代码量也不大，但它完整覆盖了一个静态站点该有的环节： 结构、样式、响应式、数据驱动和部署。做完之后，我对“页面是怎么来的”这件事清楚了很多。

如果继续迭代，我打算按这个顺序往下走：

  • 给文章页加上代码高亮和上一篇 / 下一篇导航；
  • 把 Tailwind CDN 换成构建版本，减少首屏体积；
  • 增加标签筛选和搜索，文章多了之后会更好找；
  • 补充 RSS 和站点地图，方便订阅与收录。

最后想说，个人主页不需要一次做到完美。先把第一版推上线，再慢慢改， 这本身也是学习的一部分。
